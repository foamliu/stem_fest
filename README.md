### 4.2 H3 出视频「照抄即可」参数表

| 参数 | **必须用** | 说明 |
|------|:---:|---|
| `steps` | **4（静态/单人/对话镜）/ 10（角色镜抽卡）/ 20（环境剧变镜）** | ⚠️ **不是一刀切**；MCP 签名默认值 `20` **不是配方**。<br>耗时（1056×608）：`4 步 ≈ 3.4 分` · `10 步 ≈ 9.5 分` · `20 步 ≈ 18–26 分`（近线性）<br>★ 镜 4「纸飞机掠过校园」实测 `4 步 ❌ → 10 步 ❌ → 20 步 ✅`（航拍跟拍、画面持续剧变） |
| `megapixels` | **0.6** | → 1056×608；0.92(720p) **必 OOM**。要 1080p 生成后超分 |
| `aspect_ratio` | `"16:9 (Widescreen)"` | |
| `duration` | 该镜时长（`storyboard.md`） | **帧数只能是 `17k+5`**：`2s→56` · `3s→73` · `4s→107` · `5s→124` · `6s→158` · `7s→175` · `8s→192` · `9s→226` · `10s→243`<br>⚠️ **6s 比 5s 实际贵 1.41s**，别随手写 6s。<br>**长台词镜可放宽到 10s**（如镜 99/101，各 31 字）—— 越长越费时也越容易漂，只给长台词长镜头用 |
| `ref_image_1` | 角色 / **对话双方合影** → `<Picture 1>` | 竖版头肩特写可直接用，**不必**裁 16:9 |
| `ref_image_2` | 该镜场景图 → `<Picture 2>` | 无角色镜走 `t2v` |
| `prompt` | `CUT 1:` + **景别**（照抄 `storyboard.md` 的景别列）+ 动作 + `Audio:` 台词原文 | 环境音不一定生成，见 §6；一镜一个主景别，定义见 storyboard「景别列读法」 |

**★ 参考图新规则（2026-09-13，同日二次修正）**：**多人场景内的镜，参考图必须让人物齐全** ——
H3 靠参考图认识「画面里有谁」，**只给说话人一张脸 ⇒ 其余人凭空消失、变成对着空教室说话**
（用户实测反馈）。规则分三档：

| 镜型 | 参考图 | 备注 |
|---|---|---|
| **两人对白镜** | **对话双方合影** | 只给一方，另一人会消失、眼神也对不上 |
| **多人场景里的「单人说话镜」** | **该场景的全体合影**（如 `four_students`，四小强） | prompt 里写明「**身后和身旁还站着另外三位同学，他们安静看着、不说话，只入画一部分**」 |
| **面部特写（close-up）** | 单人定妆照即可 | 特写下旁人本就不该入画 |

⇒ 本轮复核后多人镜 **88/129**、去重 **28 种组合**（见 §8 P0）。

**★ 看图与验收（三条路，按优先级）**

1. **主模型直接读图**（最快）—— ⚠️ 每条会话图片额度有限，实测读 **~7 张**后静默丢弃，**新开会话恢复**。
   省额度：只读关键的、大图先缩到 ≤1024 px（`OUTPUT/_view.py`）、**多张拼成 montage 再读**。
2. **本地 `qwen3.5:latest`**（可脚本化的批量核查）—— 用法与踩坑见 `ASSETS/README.md` §7。
   ⚠️ **"多选一"分类可靠；排序 / 打分 / "像不像"不可靠**（有位置偏置）。
   ⚠️ **跑批期间绝对不要调它**：常驻 5.5 GB 显存会把 H3 挤爆（空闲要 ≥6 GB、功耗 ≈95–100 W）。
3. **数值法**（客观可复现，额度耗尽时首选）—— 用 PIL 现算：整图 RGB 均值 / 饱和度、
   局部四角取样（背景明暗冷暖）、土壁 G/R 比、天空 std、主体亮部占比。
   ★ 调色锁定就是靠这套量化出来的（`trench_wide_v02`：gain RGB (0.930, 1.050, 0.995)，
   土壁 G/R 由 0.946 → 1.068）。**脚本是可丢弃的**，量完即删，别囤在 `OUTPUT/`。

## 6. 已知坑与硬约束（都是实测踩出来的，别重犯）

### 6.1 ComfyUI / 工具侧

| # | 约束 | 说明 |
|:-:|------|------|
| 1 | ★★ **定妆照 = 外形的唯一权威；prompt 禁止改动外形** | 造型基串只能写**客观可见的稳定特征**（性别 / 发型发色 / 服装 / 配饰）。**严禁**写体型、脸型、胖瘦、年龄感。<br>**反面案例**：镜 15 prompt 写了"圆脸、偏胖"（定妆照实为瓜子脸）→ 生成结果**胖一圈、脸变圆** |
| 2 | **H3 `megapixels` ≤ 0.6** | 16GB VRAM 下 0.92 必 OOM；要 1080p 生成后超分 |
| 3 | **H3 R2V 最多 2 张参考图** | ≥2 人镜 ⇒ 必须合成**一张**合影。<br>**定案做法**：**直接向用户要现成 AI 合影**。❌ **不要**用 LongCat 做多脸拼图合成（实测**身份全丢**）；「单人出图 + 程序抠人贴底图」为备用（脚本用完即弃，现写现跑） |
| 4 | **角色镜必须引用定妆照** | 否则每张脸随机变化，定妆照白做 |
| 5 | **上传不覆盖同名文件** | 同名存为 `名字 (1).png`。**换图后先删 `E:\code\ComfyUI\input\名字.png` 再上传** |
| 6 | **输出规格以 `ffprobe` 实测为准** | 不要相信注释里的分辨率 |
| 7 | **长任务用 `wait=False`** | 先拿 `prompt_id`，再用 `comfyui_get_result` 取回 |
| 8 | ★ **启批处理前先看清任务数；跑完确认进程退出 + 队列清零** | 曾发生：脚本实参是 8 个镜头却被当成 2 个，且**进程后台存活**，LongCat 首帧任务与 H3 视频任务在队列里**交替执行**，每个还要重载 11.96 GB 模型 ⇒ 纯浪费。<br>**纪律**：① 启脚本前 `--dry` 看清任务数；② 跑完用 `Get-CimInstance Win32_Process` 核进程、查 `/queue` 与 `/history`；③ 不同 batch 输出前缀要可区分 |
| 9 | ★ **清队列姿势** | 删**排队中**：`POST /queue {"delete":[prompt_id]}`；<br>中断**正在执行**：先 `POST /interrupt`（空 body）再删队列 —— **只发 delete 删不掉 running 那个**；<br>清历史：`POST /history {"clear":true,"delete":[id,…]}` |
| 10 | ★★ **`steps` 按镜头类型选（4 / 10 / 20），不照抄签名默认值** | 见 §4.2。**耗时的真正决定变量是 steps × 帧数**，不是"模型比显存大" |
| 11 | ★ **跑批期间不要调 ollama 视觉模型** | `qwen3.5` 常驻 5.5 GB，会把显存挤到 76 MiB、功耗掉到 30 W。<br>用完必须 `Stop-Process -Id <llama-server PID> -Force`（`ollama stop` 会卡在 `Stopping...`） |
| 12 | ★ **H3 输出分辨率由 `ResolutionSelector` 反推** | `√(megapixels×1024²/(16×9))` 取 32 的整数倍：`0.6→1056×608`、`0.4→832×480`、`0.3→736×416`、`0.2→608×320` |
| 13 | ★ **帧数只能是 `17k+5`** | 公式 `max(5, round(时长×24)) + (5 - (max(5, round(时长×24)) % 17)) % 17`（`workflows/video_minimax_h3_r2v.json` 节点 131）<br>⚠️ 旧文写的「5s→136 帧 / 6s→136 / 7s→170」**是错的**，实测 `124 / 158 / 175` |
| 14 | **TTS `custom_speaker_name` 必须为空** | 仅在使用 `qwen3_tts` 时适用；该字段是音色 mixing 列表，填自定义名 → `ValueError` |
| 15 | **H3 不一定生成环境音** | 镜 15 实测：只念了台词，前后段 ≈ −50 dB ⇒ **环境音另做**（`ace_step_t2audio` 或现成音效），剪辑时与台词对齐 |

### 6.2 素材 / 文件侧

| # | 约束 | 说明 |
|:-:|------|------|
| 1 | **全 ASCII 命名** | 中文/空格文件名会被上传接口改成随机 `mcp_ref_<hex>.png` |
| 2 | **跨格式哈希不可比** | png 与 jpeg 的 SHA256 天然不同 → 防呆要比**解码后的像素** |
| 3 | 尺寸不同时比**归一化相似度** | 缩到 256×256 算平均像素差；<5 疑似同图，>15 明显不同 |
| 4 | 三视图拼版有风险 | 三角度可能被 `image_edit_longcat` 一起画进新镜头；预案：裁正面格另存 `<slug>_front_v01.png` |
| 5 | Downloads 里常有同名 `(1)/(2)/(3)` | 入库前**必须哈希/像素比对**（曾发生"两个角色共用一张图"的险情） |
| 6 | ★ **能裁就别修** | 画面内文字/水印落在空白区时**直接裁掉那条带**最可靠；任何"拟合填充"都留伪影。<br>裁前量"可裁边界"：**文字下界 < 裁切线 < 主体上界** |
| 7 | ★ **"自动检测画面内文字"会误伤人脸** | 通用"深色小连通域 + 聚类"会把**发丝边缘**当文字。<br>正解 ＝ **先区域约束定位** + **强校验「框外像素与源图逐像素完全相同」** |

### 6.3 系统 / 脚本环境侧

| # | 坑 | 解法 |
|:-:|----|------|
| 1 | 单条命令 **30 秒超时** | 长任务用 `Start-Process` 后台跑 + 轮询状态文件 |
| 2 | PS 5.1 读**无 BOM 的 UTF-8 `.ps1`** 按 GBK 解析 → 中文致语法错误 | 脚本改纯 ASCII，或用 Python |
| 3 | `Invoke-RestMethod` 发中文变 `???????` | body 用 `[Text.Encoding]::UTF8.GetBytes()`，或直接用 Python |
| 4 | `>` 重定向在 PS 5.1 写 **UTF-16** | 用 Python 写 UTF-8，或 `Out-File -Encoding UTF8` |
| 5 | **robocopy 会预分配目标文件** | 中断后是"长度正常但内容为零"的假文件；**重拷前先删目标同名文件** |
| 6 | `ollama pull` 的 ANSI 进度条让 PS 报错 | 用 `Start-Process` 分离进程 |
| 7 | **Ollama 桌面版的模型路径不读环境变量** | 改 `%LOCALAPPDATA%\Ollama\db.sqlite` 里的 `settings.models` |
| 8 | `qwen3.5` 不关 thinking 会返回**空字符串** | 请求体加 `"think": False` |
| 9 | 控制台中文乱码 ≠ 文件损坏 | PS 5.1 用 ANSI 读 UTF-8 的显示问题；用 `read_files` 或 Python 复核 |

## 7. 推荐生产流程（逐镜）

```
① 查 storyboard.md 该镜的「参考图提示」列 → 确定要什么素材
        ↓
② 出分镜图（有角色 → image_edit_longcat；无角色 → z_image_turbo_t2i）
   · image = 该角色定妆照 / **对话双方合影**
   · prompt = **景别（必须写死）** + 场景 + 表情动作 + 风格后缀（勿用文字描述长相）
   · seed = 角色卡里的固定 seed ｜ megapixels = 1.5（→1680×944）
   · ★ 验收：输出画面**脸高 ≥ 250 px**（位置法量）
        ↓
③ 出视频（音频这一步就生成了，不要另做配音）
   · 有角色 → video_minimax_h3_r2v；无角色 → t2v
   · ref_image_1 = 角色/合影图 → <Picture 1>｜ref_image_2 = 场景图 → <Picture 2>
   · prompt = `CUT 1:` + 景别 + 动作 + **Audio**（环境音 + 台词原文）
   · 参数照抄 §4.2（尤其 steps）
        ↓
④ 音频：① 片段内台词 + 环境音 → 写进 H3 prompt
        ② 跨镜 BGM → 现成音源，后期铺整段
           · 序幕（镜 1-9）：Forrest Gump Suite (Feather Theme) / Alan Silvestri
           · 尾声（镜 126-129）：《如愿》/ 王菲（词 唐恬、曲 钱雷）
           · ⚠️ **片尾必须标注原作者与作品名**，仅限校内非商业展示
        ↓
⑤ 剪辑：按镜号顺序拼接（相邻用尾帧/首帧衔接）→ 铺 BGM → 音量平衡 → 循环播放
```
